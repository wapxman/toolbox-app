# ТЗ: Магазин, покупка и доставка — Taketool 1.1

Версия 1.0 от 21.09.2026. Статус: **на утверждение**.
Макеты: канвас «Taketool: Магазин и доставка» (9 экранов).

## 1. Цель

Один инструмент можно **арендовать** или **купить**, а получить — **из бокса** (как сейчас) или **с доставкой по Ташкенту за 50 000 сўм**. Оплата Payme и Click на всё. Существующий сценарий «аренда из бокса» не ломается.

## 2. Что меняется в приложении

### 2.1 Навигация

| Было | Стало | Что внутри |
|---|---|---|
| Главная | Главная | Карта боксов, без изменений |
| Поиск | **Магазин** | Каталог всех инструментов, поиск, категории, переключатель «Аренда / Покупка» |
| Сканер | Сканер | Без изменений |
| Аренды | **Заказы** | Аренды, покупки и доставки в одном списке |
| Профиль | Профиль | Без изменений |

Поиск не исчезает: строка поиска стоит наверху Магазина, а на Главной остаётся поле над картой.

### 2.2 Магазин (экран 2)

- Каталог всех инструментов всех боксов, сетка 2 колонки: фото, название, цена аренды в день, цена покупки, статус.
- Переключатель «Аренда / Покупка» меняет только крупную цену на карточке и фильтр: в режиме «Покупка» показываем только инструменты с заданной ценой продажи.
- Категории чипсами из поля `tools.category`.
- Баннер «Доставка по Ташкенту — 50 000 сўм, самовывоз бесплатно».
- Статусы: «Свободен», «Занят до DD.MM» (по `expected_end` активной аренды), «Продан» не показываем вовсе.
- Гостю всё видно без входа. Вход просим только на кнопке «К оплате».

### 2.3 Карточка инструмента (экраны 3 и 3б)

1. Фото, название, бренд • категория, статус.
2. Сегмент **Аренда | Покупка**.
   - Аренда: цена/день, степпер дней 1–30, скидки как сейчас (−20% от 3 дней, −35% от 7, из `app_settings.pricing`).
   - Покупка: цена продажи, состояние, комплект, гарантия (текстовые поля из админки).
3. Блок **Как получить**: «Забрать из бокса — 0 сўм» / «Доставка по Ташкенту — 50 000 сўм».
4. Нижняя панель: итого и кнопка. При доставке кнопка «Указать адрес», при самовывозе «К оплате».
5. Подсказка: срок аренды начинается с момента получения (открытие ячейки или передача курьером).

### 2.4 Доставка (экран 4)

Поля: адрес (текст + кнопка «Указать на карте», пин на Яндекс-карте), подъезд, этаж, квартира, телефон получателя (по умолчанию из профиля), комментарий курьеру, интервал.

Интервалы: сегодня 14–18, сегодня 18–22, завтра 10–14, завтра 14–18, завтра 18–22. Интервал «сегодня» доступен, если до его начала больше 2 часов. Список интервалов и порог — в `app_settings.delivery`, чтобы менять без релиза.

Проверка адреса: точка должна попадать в границы Ташкента (полигон в `app_settings.delivery.city_polygon`). Если нет — «Пока доставляем только по Ташкенту».

### 2.5 Оформление (экран 5)

Сводка: товар, режим (аренда N дней / покупка), способ получения с адресом и интервалом, разбивка суммы (товар, скидка, доставка, итого), выбор Payme / Click, согласие с офертой, кнопка «Оплатить N сўм». Логика оплаты та же, что в `payment_screen.dart`: Payme открывает ссылку, Click шлёт счёт в Click Up, экран поллит статус 2 минуты.

### 2.6 Статус заказа (экран 6)

Таймлайн: Оплачен → Собран → Курьер в пути → Доставлен. Карточка курьера с кнопкой звонка. Кнопка «Отменить заказ» видна только до статуса «Курьер в пути». «Написать в поддержку» ведёт в Telegram/телефон из `app_settings.support`.

Для аренды с доставкой после «Доставлен» заказ превращается в обычную активную аренду: срок, продление, возврат.

### 2.7 Заказы (экран 7)

Вкладки «Активные / История». Карточка: фото, название, тип (аренда N дней / покупка), способ получения, статус-чип, сумма. У активной аренды кнопка «Вернуть». Тап открывает статус заказа или детали аренды.

### 2.8 Возврат (экран 8)

Два варианта: «Сдать в бокс — 0 сўм» (как сейчас: QR, ячейка открывается) и «Вызвать курьера — 50 000 сўм» (адрес и интервал как при доставке, оплата сразу). Аренда завершается по факту: ячейка закрылась или курьер отметил «Забрал». Штраф за просрочку считается на дату возврата, как сейчас.

## 3. Бизнес-правила

1. **Один физический экземпляр.** Инструмент либо в аренде, либо продан, либо свободен. Покупка занятого невозможна, аренда проданного невозможна.
2. **Цена продажи** задаётся в админке (`tools.sale_price`). Нет цены — инструмент только в аренду.
3. **Доставка 50 000 сўм** фиксированная, для аренды и покупки, по всему Ташкенту. Значение в `app_settings.delivery.fee`.
4. **Срок аренды с доставкой** стартует от `delivered_at`, а не от оплаты. `expected_end = delivered_at + days`.
5. **Отмена** клиентом: до статуса «Курьер в пути». Возврат денег — вручную из кабинета Payme/Click, заказ переходит в `cancelled` с пометкой `refund_pending`, админ ставит `refunded`.
6. **Максимум 3 активных** аренды на пользователя остаётся; покупки не считаются.
7. **Демо-аккаунты** (`REVIEW_ACCOUNTS`) могут оформить заказ, но доставка им не назначается.
8. Проданный инструмент: `tools.status = sold`, ячейка освобождается после того, как курьер или админ забрал его из бокса.

### 4.3 Изменения в `rentals`

| Поле | Описание |
|---|---|
| `order_id` uuid null | Ссылка на заказ |
| `fulfillment` text default `pickup` | |
| `return_method` text null | `box` / `courier` |
| `return_order_id` uuid null | Заказ на вызов курьера при возврате |

Статус `pending_delivery` добавляется: аренда оплачена, но ещё не передана. В `active` переводит курьер/админ при доставке.

### 4.4 Статусы `orders`

```
pending_payment → paid → packed → dispatched → delivered
                 ↘ cancelled (до dispatched)
```

Для `fulfillment=pickup` заказ проходит `paid → delivered` сразу при оплате (ячейка открылась).
Для `kind=buy` после `delivered` инструмент получает `status=sold`.

### 4.5 `app_settings`

Ключ `delivery`:
```json
{"fee":50000,"slots":[["10:00","14:00"],["14:00","18:00"],["18:00","22:00"]],"same_day_min_hours":2,"city_polygon":[[41.20,69.10],...]}
```
Ключ `support`: `{"telegram":"https://t.me/...","phone":"+998935236060"}`.

## 5. API (toolbox-backend)

### 5.1 Новое

| Метод | Путь | Кто | Что делает |
|---|---|---|---|
| GET | `/api/tools` | все | Каталог с `sale_price`, `category`, `busy_until`, фильтры `?q=&category=&mode=rent|buy` |
| GET | `/api/settings/delivery` | все | Тариф, интервалы, полигон |
| POST | `/api/orders` | юзер | Создать заказ (`tool_id, kind, days, fulfillment, provider, delivery{...}`). Возвращает заказ и то же, что `POST /rentals` для оплаты (ссылка Payme или счёт Click) |
| GET | `/api/orders` | юзер | Свои заказы, `?status=active|history` |
| GET | `/api/orders/:id` | юзер | Детали + таймлайн |
| GET | `/api/orders/:id/payment-status` | юзер | Как у аренд |
| POST | `/api/orders/:id/cancel` | юзер | Только до `dispatched` |
| POST | `/api/rentals/:id/return-courier` | юзер | Создаёт заказ `kind=return`, `delivery_fee=50000`, оплата |
| PATCH | `/api/admin/orders/:id` | админ (`X-Admin-Secret`) | Статус, курьер, `refund_status` |
| POST | `/api/admin/orders/:id/open-cell` | админ | Открыть ячейку для сборки заказа |

### 5.2 Что меняется в существующем

- `POST /api/rentals` остаётся для обратной совместимости старых версий приложения, внутри создаёт `order` с `fulfillment=pickup`.
- `payme.js` и `click.js`: `merchant_trans_id`/`account.order_id` теперь ищут сначала в `orders`, потом в `rentals`. `PerformTransaction`/`Complete`:
  - `pickup + rent` → как сейчас: аренда `active`, ячейка `occupied`, замок открыт;
  - `pickup + buy` → заказ `paid`, замок открыт, инструмент `sold`, ячейка `free` после закрытия;
  - `delivery` → заказ `paid`, аренда `pending_delivery`, замок **не** открывается, уведомление админу.
- `cron.js`: просрочка считает только `active`; `pending_delivery` не трогает. Новый крон: заказы `paid` без движения 24 часа → уведомление админу.
- Уведомления пользователю на каждой смене статуса заказа (таблица `notifications`, как сейчас).

### 5.3 Уведомление админа

Telegram-бот в группу операторов: «Новый заказ № 1042: шуруповёрт, аренда 3 дня, доставка сегодня 18–22, ул. Бабура 45, +998…». Токен и chat_id в env `ADMIN_TG_TOKEN`, `ADMIN_TG_CHAT`.

## 6. Админка (toolbox-admin)

1. **Инструменты**: поля цены продажи, состояния, комплекта, гарантии.
2. **Заказы** (новый раздел): список с фильтрами по статусу и дате интервала; карточка заказа: кнопки «Собран» (+ «Открыть ячейку»), «Передан курьеру» (поля курьера), «Доставлен», «Отменить», «Возврат сделан». Для возврата курьером: «Забрал у клиента» → аренда `completed`, ячейка ждёт возврата в бокс.
3. **Настройки**: тариф доставки, интервалы, полигон (пока JSON-поле).
4. Дашборд: выручка отдельно по аренде, продажам и доставке.

## 7. Совместимость и версии

- Приложение 1.0.5 продолжает работать: старые эндпоинты не меняют контракт, новые поля в ответах только добавляются.
- Релиз приложения **1.1.0+9**: сначала внутренний тест Play + TestFlight, потом Production.
- Бэкенд деплоится раньше приложения. Порядок: миграции → бэкенд → админка → приложение.

## 9. Открытые вопросы

1. Кто курьер: свой сотрудник или Яндекс Доставка? От этого зависит, нужна ли интеграция или достаточно ручного назначения в админке.
2. Цены продажи и тексты гарантии по каждому инструменту.
3. Нужна ли предоплата залога при аренде с доставкой (инструмент уезжает к клиенту без визита к боксу).
4. Границы доставки: весь город или исключить дальние районы.
5. Работаем ли по выходным и какие интервалы.
